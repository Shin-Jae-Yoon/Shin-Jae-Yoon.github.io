# 고쳐 쓴 예시

`language/oop/static.md`를 규칙에 맞게 옮긴 실제 기록이다. 고치기 전 위반은 세 가지였다.

```
허용되지 않은 섹션: 왜 필요한가, 이름이 여럿이다, 메모리 영역과의 관계,
                    클래스 메서드, static 블록, 변수의 유효 범위
볼드 과다: 22개 (예산 5)
리드 문단에 볼드
```

## 리드

```
전  **인스턴스마다 따로 생기는 것이 아니라 클래스 전체가 공유하는 것.**

후  인스턴스마다 따로 생기지 않고 클래스 전체가 하나를 공유하는 것.
```

볼드를 걷어내면 문장이 그대로 남는다. 굵게 하지 않으면 안 읽힐 것 같아서 굵게 했던 것이지, 굵을 이유가 있어서가 아니다.

## 섹션 여섯 개를 셋으로

```
왜 필요한가            →  ## 왜
이름이 여럿이다        →  ## 왜 의 끝 문단으로 흡수
메모리 영역과의 관계   →  ## 어떻게
클래스 메서드          →  ## 어떻게
static 블록            →  ## 어떻게
변수의 유효 범위       →  ## 한계
```

여섯 개 중 셋은 독립된 절이 아니라 `## 어떻게` 안의 문단이었다. 제목을 붙이면 목차는 그럴듯해지지만 글은 토막 난다.

## 표를 문장으로

두 열짜리 표는 문장이 더 짧다.

```
전  | 영역 | 무엇이 들어가나 |
    | --- | --- |
    | **메서드 영역** | 클래스 정보, 클래스 데이터, **클래스 변수** |
    | **호출 스택** | 메서드 작업에 필요한 공간. **지역 변수, 매개변수** |
    | **힙** | 인스턴스가 생성되는 공간. **인스턴스 변수** |

후  JVM은 메모리를 용도에 따라 나눠 관리한다. 클래스 정보와 클래스 변수는
    메서드 영역에, 메서드가 쓰는 지역 변수와 매개변수는 호출 스택에,
    생성된 인스턴스와 그 인스턴스 변수는 힙에 놓인다.
```

세 열짜리 유효 범위 표도 마찬가지로 두 문장이 되었다. 표는 축이 진짜로 둘일 때만 남긴다.

## 인용 블록을 본문으로

```
전  **제약이 있다.**

    > **클래스 메서드 안에서는 인스턴스 변수를 쓸 수 없다.**

    클래스 메서드는 인스턴스보다 먼저 존재할 수 있는데, 그 시점에
    인스턴스 변수는 아직 없기 때문이다.

후  클래스 메서드 안에서는 인스턴스 변수를 쓸 수 없다. 클래스 메서드는
    인스턴스보다 먼저 존재할 수 있고, 그 시점에 인스턴스 변수는 아직
    없기 때문이다.
```

`제약이 있다` 하고 인용 블록으로 한 번 더 말하는 것은 같은 말을 두 번 하는 것이다. 주장과 근거를 한 문단에 붙이면 인용 블록이 필요 없다.
